## 三步体验本地 AI

1. 在发布页下载 **DeepSeekQuotaGuardAI-0.2.0a1-windows-x64.zip**，完整解压到可写的新文件夹，运行 **DeepSeekQuotaGuardAI.exe**。不要只取出 EXE，也不要覆盖旧程序或旧账本。GitHub 自动生成的 Source code 不含模型和浏览器。
2. 点击 **诊断日志 / 本地 AI → 本地 AI 助手**，选择「教学示例 · 删除准备」或「教学示例 · 读取费用」。先看“程序记录的事实”，再点 **本地 AI 解释**。只有这一步会加载模型，无需登录、安装模型服务或另外下载权重。
3. 比较事实与建议：例如 Harness 是应用托管项，程序在准备阶段就拒绝普通删除；助手可以把“为什么这是 Harness 管理项”排在前面，但改不了事实。模型文件不全、超时或输出不合格时，界面明确显示改用了规则建议。

**这个 AI 做到什么程度？** 它读一条诊断的六项分类，从预先写好的相关说明中选一条优先展示；所有合格建议都保留。它看不到日志原文、姓名、Cookie、密钥或账本，没有聊天、浏览器操作、改规则或删除权限。模型不是 DeepSeek 的云端 API，也不使用 DeepSeek Harness。在本机的 30 次合成试验中，30 次均返回允许的主题，仅 16 次首选与开发者预选一致；没有证据表明 AI 顺序比固定顺序更好。详情见[开发教学](docs/local-ai-guide.md)。

## 连接自己的控制台前

先阅读上方使用限制和[使用说明](使用说明.md)。在新目录创建列表，填写自己要管理的 Key 在平台上的**名称**和个人额度，不要把完整密钥填入表格。空姓名或 `-1` 跳过管理；`0` 是零额度，开启自动管理后可能立即触发删除。

完成填写后登录程序打开的独立浏览器，点击左侧 **API keys**，进入列表后再点一次页面空白处，然后回软件点击 **读取费用**。这是帮助独立浏览器看到正常控制台请求的操作顺序，空白处本身不是授权按钮；是否成功以程序的核验结果为准。先做只读检查，弄清费用、目标和提示，再决定是否启用自动管理。团队需要请求前配额时，请阅读上方的「替代方案建议」。

建议学习或小范围验证时使用独立、空闲的 Windows 电脑。没有验证同时进行其他操作的所有影响。发现问题，请在[新版 Issues](https://github.com/xml-nya-meow/deepseek-quota-guard-ai/issues/new/choose)提交版本、时间、复现步骤、固定原因码和已经脱敏的必要日志；不会脱敏时只写文字。

## 恢复与多 Key 调度的开发状态

开发源码保持全自动管理：一次启动后，按原规则处理已到线的 Key，无需逐枚审批。同一轮有多个合格目标时，先后按确认批次、稳定 Tracking ID 排序；每处理完一枚就继续核验下一枚。人员表空行、跳过行和页面乱序不决定删除对象。遇到结果未知、原操作未结清、证据过期或表格变化时，继续沿用停止、刷新或核实流程。当前每个管理窗口只有一个删除执行任务，不并发提交。

新操作在签发一次性许可前，将准备阶段核验过的目标和独立对照身份与原 `operation_id` 一起保存。重启后核实沿用这份证据，并重新取得相关目标的本机互斥。它不是重新删除的许可，也不能保证对照已消失时仍能确认旧结果。旧版操作没有保存过的证据不会凭空补齐。

预测目前仅写入独立的本地 `forecast-shadow.sqlite3`，不决定是否删除、不修改额度，不会依据预测结果推迟已达额目标，也不参与处理顺序。当前正式读取链没有可信的统计截止时间，因此显示时间未知、不给出 ETA。反复读取相同费用不算新的有效消费样本。该文件虽使用散列标识，仍包含费用与时间等本地数据，反馈问题时不要直接公开上传。

`-1`、空姓名继续跳过；`0` 保持零额度规则；正额度沿用原费用完整性与到线判定；强制删除仍是独立的选中目标操作，不要求达到额度，但必须通过身份和未决操作核验。离线 100 枚模拟目标连续处理的检查不等于真实平台吞吐、停费速度或生产验收。
