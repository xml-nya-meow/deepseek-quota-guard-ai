# 0.2.0a1：从经典版分出内置本地 AI 版（2026-11-04）

## 一、实际改动

经典版止于 dev19，在原仓库保留[源码和教学文档](https://github.com/xml-nya-meow/deepseek-quota-guard/tree/classic-dev19)。新版沿用额度管理、账本与平台身份核验，从已经审计的源码和空模板起步；公开源文件与发行包分开，均不需要复制旧账本或浏览器资料。

新版诊断窗口可选一条历史事件或两个教学示例。每次只将六项分类交给本机模型，从允许的建议中选出先读的一条，其他建议仍全部显示。模型按需加载，两条 CPU 线程，超时退出。损坏、非法结果或不能运行时清楚提示改用规则说明。Windows 发行包含固定版本的 Qwen 模型、llama.cpp 引擎及许可证；普通使用者无需安装服务。

## 二、改动理由

“平台返回费用”“程序确认到线”“允许提交删除”“平台列表已无此目标”是不同的事实。模型适合解释记录，不能从模糊提示推断 Key 已经删除。经典版中网页与 HTTP 的列表顺序不同，Harness 项也没有普通删除权限；这些约束仍应依靠完整标识、类型与一次性许可核验。模型不能发起网络操作、选择目标、写账本或要求软件自动重试。详见[教学向实现说明](local-ai-guide.md)。

## 三、已经运行的验证

- 通过真实 Windows GUI 按钮，在教学示例中启动了随包同源的本地模型；本机一次从点击按钮至显示 Harness 建议约 1.23 秒，无须账号。
- 15 类合成事件分别以两种选项顺序运行：30/30 次返回事件允许的主题，16/30 次首选与预选一致（常用顺序 12/15，反转 4/15）。单次约 1.05–1.22 秒，观察到推理子进程峰值工作集约 506 MiB，仅代表这台机器；这不是整款软件的内存需求或故障诊断准确率。
- GUI 与相关流程定向核验 40 项通过。引擎定向核验覆盖输入和输出越界、资产损坏、额外 DLL 和超时清理。在联测中发现了原先启动进程后再加入 Windows Job 的时序问题；改为挂起创建、加入 Job，再恢复初始线程，并验证超时后子进程也退出。

## 四、仍未解决或未验证的事项

新版本没有使用真实账户发起付费请求、预检或撤销；已知的经典版真实成功不能代替本版本的端到端验收。正额度跨线后的周期自动撤销、真实 Excel 模板导入、控制台 200 项以上清单、平台将来的新类型、低配或干净 Windows 机器及长时间无人值守均未验收。已有适配器对超出核验能力的列表会停止。撤销是真实平台操作，不能恢复，也不能拦截在途请求。

本地助手目前只能解释已有诊断类别，排序受候选顺序影响。没有验证它会提高实际现场排查的成功率。若打不开程序或遇到故障，请向[新版 Issues](https://github.com/xml-nya-meow/deepseek-quota-guard-ai/issues/new/choose)提供版本、原因码和操作步骤；勿贴令牌、Cookie、姓名、完整日志或用户目录。
