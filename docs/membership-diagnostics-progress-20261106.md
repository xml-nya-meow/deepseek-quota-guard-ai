# 成员恢复错误分类修复（2026-11-06）

## 实际改动

成员计划保存前预检、已保存计划的读取、写入、最终复核、日志导出分别使用固定脱敏原因码。显式的身份、回执、共享结构和锚点错误仍保持原原因码。

## 改动理由

真实 `DataStore.export_logs()` 将文件 I/O 错误转为 `GuardError`，它继承 `ValueError`，此前被共享事务误归为 `REGISTRY_INVALID`。这会让可修复的本地导出问题看起来像共享登记损坏。现在仅在成员计划回调边界分类，不放宽责任锁、删除许可或完整性校验。

已保存计划发生导出故障时，成员见证可能已提交；恢复日志写入条件后应沿用原计划，不能清空登记。计划建立前失败则明确说明本次计划尚未保存，不承诺已经具备同计划自动恢复的证据。
