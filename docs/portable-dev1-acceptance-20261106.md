# 0.2.0a2.dev1 → dev2 成品离线验收（2026-11-06）

## 实际改动

1. [成员恢复错误分类](membership-diagnostics-progress-20261106.md)：本地读写、日志导出和真正的共享登记损坏分开诊断，原计划和责任规则不变。
2. 增加独立 `--offline-acceptance` 模式，以真实 App、Excel 解析器、SQLite、责任 Gate 和单次删除许可执行成品验收。浏览器传输为合成实现，禁止构造真实平台浏览器并阻止 Python socket 连接。
3. 所有夹具只创建在新的 `offline-acceptance-*` 目录；已有目录和链接路径被拒绝，责任登记显式注入。普通 `--smoke` 同样要求显式新目录，并记录 Tk 回调及关闭结果。
4. 新增 `tools/verify_portable_candidate.py`，依次检查 GUI、捆绑 Chromium、本地模型、离线业务闭环；仅接受完整、版本一致的成功证据。CI 的手动成品任务复用此脚本。
5. 构建污染检查加入责任登记、成品验收夹具及结果文件；源码忽略这些运行数据。候选版本提升为 `0.2.0a2.dev1`，旧包不覆盖。
6. dev1 首次成品验收发现长隔离临时路径导致 Chromium `ENAMETOOLONG`。在保持原目录所有权的条件下采用经 samefile 核实的 Windows 既有短别名；无别名回退原路径并给明确错误提示。修复包另标 `0.2.0a2.dev2`，见 [根因与验证](browser-temp-path-progress-20261106.md)。

## 改动理由

源码测试通过不能证明冻结后的 EXE 包含所需模块、模板、浏览器和模型。此前成品自检也未覆盖 Excel 导入、原计划恢复和完整许可边界。新验收在没有真实账户的条件下检查这些集成点，并将证据放在包外。

独立复核额外指出并补上三处假阳性或隔离风险：模拟发送必须先看到同一回执的共享 `possible_send` 和本地发送见证；检查链接目录必须发生在解析路径之前；GUI 自检不能只靠 marker 和退出码，必须检查回调错误、窗口销毁和计时器清理。

- Excel 生成和导入通过的是软件内实际流程及合成 `.xlsx`；没有操作外部 Excel/WPS，也没有使用真实人员表。
- 干净 Windows 标准用户环境、长期挂机、同机其他程序干扰，以及断电和磁盘故障仍需独立验证。
- 计划提交前初装失败、锚点与共享数据库跨文件失配、无完整原证据的旧迁移仍保持阻断，不提供删除文件重建式解锁。
