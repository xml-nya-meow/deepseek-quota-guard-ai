# Windows 工作台、费用证据与撤销恢复验证

版本 `0.2.0a3.dev2`。本轮从 11 月 24 日费用核对预览和完整桌面草稿接续开发，沿用原有的费用、绑定、撤销及恢复规则。测试账户、平台与账本均为本机生成的示例。

## 实际改动

- 首页与费用核对页从同一份证据生成金额、状态、颜色和详情。选中对象随完整 Tracking ID 保留，表格重排或筛选后仍能核对原目标。有效金额、部分账单的下界和已过期的历史金额有各自的显示。明确未提交的强制操作也会显示在未达额度的行上。
- 处理记录可以按原操作编号读取当前账本的完整时间线。详情包含当时已记录的金额和阈值、意图、可能提交的许可，以及后续独立观察。事件跨过界面最近 200 条的显示范围仍可查到。旧记录缺少操作编号时单条显示。
- 完整 Windows 工作台集成人员编辑、Excel 导入、读费核对、开始与停止管理、处理记录和临时示例账本。便携包带有 Chromium、Qwen3-4B-Instruct-2507 Q4_K_M 网页操作模型、Qwen2.5-0.5B-Instruct Q4_K_M 诊断模型和运行引擎。
- 成品验收从同一份 EXE 启动三个用例。只读取费、正额度跨线、提交后丢回包并重开桌面窗口。验收程序独立核对示例后台实际收到的请求、程序记录的原操作编号、对照 Key 以及恢复后的新列表。
- 浏览器资源在复制前和成品验收时分别检查。发现日志、浏览器登录态、用户配置、系统缓存或文件系统链接时停止打包。开发使用的浏览器目录和用户的账本都无需清理。

## 改动理由

达到额度时，用户需要知道管理是否开启。提交阶段出错时，用户需要知道该核实哪次操作。账本记录许可后，网络传输仍可能失败。界面只有取得新的平台列表并核实目标缺席时，才展示核实结果。单看列表缺席也无法判断具体是谁移除了目标。

只读与删除的脚本回归曾通过，第一次冻结成品却在示例登录阶段失败，三个用例均为零次费用查询、零次撤销。本机示例通过 HTTP 把网页请求送到回环地址，默认的 Python URL 打开器却会初始化额外的 HTTPS 处理器。冻结后的解释器在该步骤读取开发环境特有的证书文件时抛出 `FileNotFoundError`。本地 4B 的 HTTP 客户端也经过这条初始化路径。将两处限制为各自需要的本机 HTTP 连接，保留平台 HTTPS 的原有验证。

## 仍未解决或未验证的事项

本轮仅使用合成页面、两个普通示例 Key 和一项 Harness 管理项。真实账户登录、真实计费、真实平台接受撤销，以及目标凭据在平台上失效仍需独立验证。窗口正常关闭后重新打开与断电或整个操作系统崩溃属于不同的恢复场景。100 枚 Key 同时达额的端到端等待时间、长期无人值守和未见网页布局也未完成验收。

下一轮建议先在普通 Windows 用户环境观察首次使用者能否独立走完示例，特别是能否从界面区分“达到额度”“许可可能已发出”“核实时目标已消失”。随后再对新页面布局、多个 Key 的等待时间及整进程强退作独立验收。需要反馈时，附版本、出错步骤、费用或操作的当前状态和脱敏错误码即可。
