# 窗口关闭定时器清理 · 2026-11-06

本单元基于 `7010bf4`，仍为 `0.2.0a2.dev0` 开发源码。只涉及窗口生命周期及对应验证，不改变全自动管理、额度判断或删除许可规则。

## 实际改动

- 为工作簿监视、系统主题监视、首次加载保存各自的 Tk `after` 句柄，每类任务最多保留一个待执行回调。
- 关闭开始时暂停上述任务；中断、浏览器关闭、审计或管理锁释放失败时，保留窗口并各恢复一条后台任务。恢复后台任务不会恢复自动管理。
- 浏览器清理完成、窗口真正销毁前，精确取消本窗口的生命周期任务和周期读取任务。保留关闭所需的 `wait_interrupt` / `wait_close` 回调，不扫描或取消其他 Tk 实例的任务。
- Windows CI 测试任务上限从 15 分钟增为 20 分钟。上一提交的 1135 项 CI 测试本身耗时 830 秒，连安装步骤已接近原上限；本次没有减少测试、放宽断言或修改测试成功标准。

## 改动理由

原工作簿监视没有保存句柄，且在关闭中仍会重新排程；窗口销毁后，未到期的 Tcl 脚本可能继续引用已删除的 Python 回调命令。单独停止一个主题定时器不能完整解决这个问题。明确任务所有权、暂停时机及失败后的单次恢复，可同时避免销毁后的悬空回调和重复监视链。

本次采纳两份独立评审的窗口生命周期建议，作为独立单元先完成；初始化和新增成员的持久恢复另行实现与验收。
