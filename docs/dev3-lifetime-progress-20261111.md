# dev3：创建以来累计与启动反馈（2026-11-11）

## 实际改动

- 新列表采用 `key_lifetime`：每枚受管普通 Key 从平台创建日期（UTC+8）累计至每次读取当天，持续更新；空姓名及 `-1` 仍不查询。`period` 旧账本不静默变更，通过“统计方式”创建独立后继账本切换，保留人员、额度、绑定和未决责任，原账本不改。
- 控制台只读列表提供创建时间；完整 Tracking ID 关联 HTTP 与页面身份，不按行序。只校验受管 NORMAL 项的创建时间，不要求查询具备删除字段；Harness 等旁观项不阻断普通目标，特殊目标不伪装普通 Key。
- 按创建日分组，按最多 30 天分段；256 请求计划上限、45 秒软预算，原 90 秒 worker 硬限保持。任何缺段不补零；只有所有段完整的目标才发布累计。当前没有缓存历史段，因此长期历史/很多不同创建日可能达到预算而拒绝发布。
- 逐 Key 创建时间、查询期间及费用同事务保存，禁止同 Tracking ID 创建时间漂移。schema 3 防止旧 dev2 将新口径账本当旧周期写入；schema 2 仍可读取。模式不同的快照不能混用，快照摘要包含口径与时间证据。
- 启动被阻止时显示“未开启”，共享责任失败显示弹窗，并记录固定阶段与原因码；不会自动创建或清空责任登记，不增加逐 Key 审批。
- 新增生命周期账本、采集、界面和启动反馈测试；成品离线正额度自动处理路径使用创建以来账本。

## 改动理由

11 月 10 日现场费用读取曾成功，但默认本机责任登记不存在；生产 App 的隔离复现确认登记缺失会阻止启动。旧提示仅写状态栏且缺拒绝事件，用户容易误认为按钮失效。此前试用说明也遗漏首次声明责任范围，现已补充。

用户明确选择“每枚 Key 从创建日期累计到当前时间”。过去 `start_date` 是周期起点，会排除起点之前的历史费用，与用户现需求不同。新口径中列表日期仅作账本上下文；实际费用覆盖由逐 Key 创建证据证明。平台费用是读取时已返回的账单，不等同于实时、零延迟的最终扣费。

保留原个人/公共额度规则、`-1` 跳过、零额度、强制删除与全自动删除分工。无明细但创建身份核验完整时，继续沿用原零额度规则；正额度未知不能按零元处理。元数据无效或身份变化时不取得自动管理资格。
