# 开发教学：让本地模型解释故障，怎样保住删除边界？

从一个不用登录的例子开始。打开程序的「诊断日志 / 本地 AI」，进入「本地 AI 助手」，选 Harness 教学示例。**先读事实，再按「本地 AI 解释」。** 按钮只会启动本机模型，不会打开浏览器、改账本或删除 Key。另一条示例是「费用类别待适配」。

## 第一课：一条观察到底能证明什么？

假设用户选择了一枚平台标记为 Harness 管理的 Key。删除准备环节拒绝普通删除，并发出一个固定原因码。只有记录明确来自提交之前，界面才能说“这次尚未提交”。如果同一个列表校验错误发生在提交后的核实环节，只能说平台状态未知。两次错误的文字可能很接近，后果并不一样。程序始终保留该次事件的阶段，既不拼接不同时刻的日志，也不让模型补全缺失的事实。

费用类别同理：平台返回了当前版本无法核算的类别，不表示当期花了零元、不表示账号一定不对，也不表示当前金额可以用于删除。此时可以给用户三条阅读建议：检查查询范围、核对起点、准备脱敏的问题说明。程序可以保证建议与这个问题相关，至于先读哪条，则交给用户按需启动的模型。

## 第二课：怎么把模型的权限做小

| 环节 | 交给下一层的内容 | 怎样看懂或验证 |
| --- | --- | --- |
| 分类 | 从**单条**已知事件中提取阶段、原因、费用写入情况、提交情况、核实结果、Key 类别六项枚举 | [local_ai_assistant.py](https://github.com/xml-nya-meow/deepseek-quota-guard-ai/blob/v0.2.0a1/quota_guard/local_ai_assistant.py) 中的 `case_from_event`、`DiagnosticCase`。姓名、ID、路径、密钥、日志原文不在输入格式中。 |
| 核定事实 | 由 `facts` 显示事件当时能证明的事实；`topics_for` 给出允许出现的建议 ID | 切换历史记录时先看时间。一次“列表缺席”的观察不能证明是哪次操作造成的，也不能证明没有在途消费。 |
| 本地推理 | 把六项分类和有限选项送进本地 CPU 进程。模型选出最值得先读的一项，其余保留原顺序 | [local_ai_runtime.py](https://github.com/xml-nya-meow/deepseek-quota-guard-ai/blob/v0.2.0a1/quota_guard/local_ai_runtime.py) 校验资源和输入、限制输出语法，再检查结果是否在允许列表。不会显示原始模型输出。 |
| 展示与退出 | GUI 在后台等待，核实事实始终可见。输出非法、模型缺失或超时，就使用规则原有顺序并标明来源 | 切换到另一事件后，上一事件迟到的排序不得覆盖当前选择。工作进程位于 Windows Job 中；退出或超时后清理。它不是可以调用网页或 Shell 的智能体。 |

项目没有开放自由聊天、模型工具、联网搜索或自动修复。模型也不参与定时巡检。增加一种新费用类别或可删除的 Key 类型，仍要取得相应平台证据，修改适配器，并用合成样本测试：不能因为模型说它认识就改变管理规则。

## 第三课：怎样验证它做对了事？

1. 在完全不登录的情况下分别解释两个示例，观察事实在点击前后是否相同。换一个示例时，不应出现上一条解释。
2. 在**另外解压出来的试验副本**中临时把 `local-ai` 改名。再点解释，应明确显示使用规则建议；还原目录后可再试。不要对现用账本或程序文件做这个练习。
3. 开发者可在 Windows 源码环境运行 `python -m unittest discover -s tests -p "test_local_ai*.py"`，再对已解压的包运行 `DeepSeekQuotaGuardAI.exe --ai-smoke --data-dir <新建的临时目录>`。后者真正启动模型，成功时该目录的 `ai-smoke.json` 内 `model_ran` 为 `true`。前者中使用模拟结果的检查不能替代这个步骤。
4. 复现权重、引擎和许可文件的来源，见[固定资产清单和准备方法](https://github.com/xml-nya-meow/deepseek-quota-guard-ai/tree/v0.2.0a1/local_ai)。Windows 包已经内置这些资源，使用者不需要安装模型服务或另行下载。

**一次有用的反例：** 15 类合成事件各试两种候选顺序，30 次都只返回合法主题，但仅 16 次将开发者预选的首要建议排第一；常用顺序 12/15，逆序 4/15。这测的是建议排序，不是诊断准确率，也没有证明 AI 胜过固定顺序。它解释了为什么我们让用户看到所有建议、把已核实事实放在最前面，并保留无需模型的回退路径。

想进一步理解真实平台中 `NORMAL` 与 `DSH` 的区别，以及为何不能按列表下标删除，见[经典版源码教学](https://github.com/xml-nya-meow/deepseek-quota-guard/blob/classic-dev19/docs/development-lessons.md)。
