## 单元 C：账本与自动、强制入口接入

### 实际改动

- 自动管理和强制删除共用持久登记。共享责任先占槽，本地 `pending` 与责任回执/检查点同事务保存；当次 `requested` 及日志导出成功后，写入 `possible_send`，再完成上下文复查并发一次性许可。保存过但导出失败的旧 `requested` 不可后来补发。
- 所有新版实例默认使用同一 Windows 用户的固定目录；换解压目录或新建空账本不会创建另一空范围。初次必须显式声明纳入的旧账本，仅检查所选目录。
- 原操作未知、仍存在或观察失败都保留共享责任。已持久核实缺席后，按精确 operation 与责任代次结清；本地终态已保存、共享结清中断时，重新打开原账本会补齐结清，不发平台请求。
- 每本账保存成员集合见证。新增成员时整个范围暂处于 `initializing`，写齐成员见证后才恢复可领取状态。恢复一对早于新增成员的旧登记文件时，尚存原账本见证会指出名册回退。
- 可信的继承列表核对原账本、原事件和证据，沿用原操作引用；不会登记第二项旧责任。已结历史不妨碍新列表加入。拷贝/改名不能凭路径猜测接管责任。
- 所有原有 GUI 测试显式使用临时登记夹具；新增责任测试直接实例化产品 App。测试不接触真实 Windows 用户登记。

### 改动理由

本轮解决的是独立账本绕过旧未决的路径；同时防止用永久禁用伪装修复、用已结共享槽掩盖本地旧备份、或用一次性许可之前的日志导出重试意外重发。保留 `-1` 跳过、零额度、正额度完整费用、强制免额度及全自动管理原规则；不加入逐枚人工审批。
