# Windows 费用核对预览与同页读费对照

2026-11-24。基线为 `product/4b-web-operator` 的 `799fac2`。本轮在独立工作树开发，实验使用本机 Chromium、本地模型和新建的合成账本。

## 实际改动

手动读取费用后，桌面程序打开“费用核对”。该页显示本次采样时间、账户核验状态、统计口径、公共额度的计算、受管和跳过行数、费用待补全数及达线待处理数。可按姓名或完整 Tracking ID 搜索，选中行可复制 ID、核对金额依据和本次取得的查询期间。按完整 ID 保留刷新前的选中对象。启动管理继续使用原有一次确认，以及确认后对账本、身份和费用证据的检查。

Windows 独立预览使用同一桌面组件，以临时示例账本呈现首次读取、个人跨线和公共人均额度为零三个场景。预览可筛选、搜索和选择行，不提供登录、开启管理或平台撤销入口。源码运行命令为 `python tools/preview_fee_review.py`。

为 4B 增加只读实验选项 `table`，将公开表头、单元格、完整公开 ID 与行内控件放在一起，保留表外控件及输入框当前值。选行仍由模型完成。默认读费沿用 `flat`，撤销流程沿用原表示。可用 `tools/compare_read_observations.py` 的 `--assets`、`--chromium` 和 `--output` 指定本地资产、浏览器和全新结果目录重做配对。

## 改动理由

历史费用可能已经越线，但当前快照缺少部分证据。核对页、状态栏和启动确认采用与队列一致的资格判断，让用户能区分本次可处理、仍待补全和明确跳过的目标。正额度的历史下界不会显示为当前达线待处理，个人或公共零额度沿用有效身份的独立规则。证据到期后显示历史状态。

此前模型曾重复填写日期或选错 DSH 行。本轮用同一页面的两个中性名称互换任务目标，保留两个普通 Key、一行 DSH、所有行内按钮和两个已填写的日期控件。换目标时，每种表示首次提供给模型的输入，除任务中的目标 ID 外均相同。模型权重、模板、推理参数、页面日期和顺序固定；候选未按目标过滤或重排。

两种表示均已保存对应的公开页面首帧。同一种表示切换普通目标后，两份首帧文件的 SHA-256 相同。[平铺首帧](evidence/fee-review-20261124/flat-observation.json) · [表格首帧](evidence/fee-review-20261124/table-observation.json)

耗时从开始网页读费到金额解析完成，独立记录冷启动时间。每例正确返回 1.25 元，均先重复填写一次已正确的日期，再点击正确行。表格表示的每个推理步骤少 323 个输入 token。这两个目标上的平均读费耗时减少约 15.6%，两组各完成 2/2。逐步动作、模型参数、输入摘要和本机合成后台计数见[配对结果](evidence/fee-review-20261124/paired-reads.json)。

另用默认平铺表示，从正常桌面读费入口运行真实 4B，观察到一次目标与日期正确的费用 GET。SQLite 入账 1.25 元，窗口自动打开费用核对，Cedar 个人额度 1.00 元、公共额度 5 元，显示已达线待程序复核。Maple 为 -1，显示未查询。管理开关关闭，后台写入、撤销记录和未决责任均为零，退出清理成功。运行前后 46 个产品 Python 文件的内容指纹一致。详见[桌面读费结果](evidence/fee-review-20261124/desktop-read.json)。

在 Windows 实际启动了独立预览 EXE，验证三个场景能创建并渲染，正常窗口能打开并退出。另验证搜索完整 ID、筛选待补全、跨场景切换、百行乱序后的选中对象、正额度历史下界和零额度。示例程序中的个人跨线来自两次合成账本快照。

Windows 本机完整回归 1387 项通过，0 跳过，耗时 452.889 秒。预览 EXE 在空临时目录、PATH 仅含 Windows System32 的环境中也完成了三个场景的自检，退出后该临时目录为空。[验证记录与 EXE 指纹](evidence/fee-review-20261124/validation.json)

## 仍未解决或未验证

重复填写日期仍出现在全部四例中，两个目标和一种页面布局不足以泛化速度或准确率。实际模型完成了单 Key 的读费、入账与桌面核对。仍待验证同日多目标查询、持续运行中正额度跨线后的单次撤销、回包丢失后的原操作恢复、未见布局，以及 100 枚同时达额时的端到端时延和资源占用。本轮交付物是费用核对预览，完整管理包、真实账户和真实平台撤销仍待后续验收。
