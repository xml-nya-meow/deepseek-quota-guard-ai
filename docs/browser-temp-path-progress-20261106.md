# Windows 浏览器临时路径过长（2026-11-06）

## 实际改动

本轮成品验收首次确认：长数据目录下，隔离浏览器会话的临时路径叠加 Playwright 配置目录名称，可能超过 Windows/Node 本次调用支持的路径长度。修复限定在本程序已经拥有的临时目录，不迁移真实账本、不创建外部共享目录、不修改 Windows 配置。

Windows 存在实际短路径别名时，只有该别名是绝对路径、更短、仍为目录且 `os.path.samefile` 确认为同一目录，才将它用于浏览器子进程的临时路径环境。父进程所有权记录、退出证明和回收仍使用原路径。没有有效别名则保留原路径，不猜测或自动创建别名。

启动成功后的深层文件也必须能安全清理：扫描与清理仅使用核实属于原目录的访问别名，原身份、收据及退出证明仍按原目录检查；对已解析的 DOS/UNC 路径只在边界比较时归一等价的扩展前缀，不把任意设备命名空间转换为普通路径。

Chromium 启动明确返回路径过长错误时，使用固定、脱敏、可操作的诊断提示，建议使用较短的数据路径；不再误报为笼统的平台或网络故障。其他启动错误不混入此分类。

## 改动理由

同一 `0.2.0a2.dev1` EXE 在长 evidence 目录中的 GUI 自检成功，但 Chromium 自检失败；改用较短 evidence 目录后，GUI、Chromium、模型和离线业务四类验收全部通过。进一步在源码环境直接以相同长 TEMP 启动 Playwright，复现 `ENAMETOOLONG` 的 `mkdtemp` 错误，排除了“缺浏览器资源”这一猜测。

本机对该已创建的合成临时目录查询得到：原路径 218 字符，系统短别名 110 字符，`samefile=True`。长度仅为本次样本，不作为硬编码最大长度或所有机器都支持短别名的保证。

随后真实 about:blank 进程检查又复现：短别名使浏览器成功启动后，父进程按原长拼写访问部分深层文件失败；已解析路径的 `\\?\` 前缀差异还可能触发错误的越界判断。这两项均须纳入清理复测，不能只凭启动成功宣称修复完成。

官方依据：微软说明 `GetShortPathNameW` 可先查询所需缓冲区长度，实际短路径不一定更短，也不保证存在短名；因此本程序只采用核实后的更短别名，不启用短名功能。[GetShortPathNameW 文档](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getshortpathnamew)。路径命名空间与普通 DOS/UNC 拼写的区别参考 [Windows 文件、路径和命名空间](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)。
