# 4B 网页操作便携版：使用、打包与验收边界

版本：`0.2.0a3.dev0`。日期：2026-11-13。此文说明本版设计与使用入口；成品验证结论以本轮实际验收记录为准，不沿用旧版测试数字。

**当前状态：开发备份，尚不可交付。实际 4B 的完整业务链未通过，本轮没有构建或发布可用包，不可替换 dev3 进行真实管理。** 下文目录和用户步骤是打包与交互设计，不是已经通过验收的成品承诺。完整失败记录及下一步见 [产品进展四项记录](operator-product-progress-20261113.md)。

## 1. 实际改动

本版把 4B 本地模型接入网页操作，保留程序的金额计算、到线判断、身份和完整 Tracking ID 绑定、单次提交许可、跨账本责任与恢复。正常使用不需要用户安装模型服务或配置 MCP。程序自动准备相关页面，模型依据页面观察选择下一步受限操作；网页行序不是目标身份。

预期完整便携包由以下内容组成；相应资产锁与打包接线已实现：

| 内容 | 用途 |
| --- | --- |
| `DeepSeekQuotaGuardAI.exe` 和 `_internal` | GUI、浏览器、Python 运行组件及依赖 |
| `operator-ai` | Qwen3-4B-Instruct-2507，Q4_K_M，llama.cpp 引擎、DLL、官方模板与许可 |
| `local-ai` | 保留的 Qwen2.5-0.5B-Instruct，Q4_K_M，仅用于诊断建议排序 |
| `BUILD-INFO.json` | 程序版本、源码摘要、模型清单摘要及依赖身份 |
| `README.md`、`使用说明.md`、`LICENSE`、`NOTICE`、许可文件 | 操作说明、验收边界与 Apache-2.0/第三方许可 |

模型都在本机运行，不调用 DeepSeek 的云端模型 API。控制台登录、读取账单和撤销 Key 仍需联网。4B 负责操作，0.5B 负责旧诊断教学，两者不能相互冒充。MCP 不是最终用户的安装前提。

预期用户流程（实际模型离线能力通过后，才安排成品与真实试用验收）：

1. 将完整新包解压到可写的新目录，运行 EXE，保留旧包和旧账本。不要单独移动 EXE；不要把新账本交给旧包写入。
2. 新建列表，填写预算、人数与人员表。仅首次使用且没有旧账本时，可明确勾选同时准备管理记录。已使用过的环境走“管理准备 / 恢复”，声明旧账本或恢复原登记。
3. 表格填平台 Key 名称与个人额度，不填完整密钥。空姓名与 `-1` 跳过管理；`0` 是零额度；正额度沿用原累计费用规则。斩杀线仅作为新表默认个人额度，已有人员额度不被改写。
4. 登录独立浏览器，在官方页面完成登录和必要核验后回软件读取。程序准备页面，不要求先点页面空白处。新列表按各 Key 创建日期累计到本次读取已覆盖时间，并持续更新；账单可能延迟。
5. 确认身份、绑定、费用与覆盖状态后启动全自动管理。每轮完成后按设置间隔等待，默认 10 秒。多个目标仍由程序队列顺序处理，模型不能将预计超额当成已到线，不能修改金额或绕过单次提交条件。

“强制删除选中 Key”是独立操作，不要求费用达到额度，但仍核验身份、目标和未决责任。撤销发生在平台，当前没有恢复原 Key 的渠道。是否需要管理、授权哪些目标和额度是多少由用户设置；不是模型自行扩大范围。

## 2. 改动理由

使用者需要完整软件，而非需要安装外部模型服务的原型。本次完成把固定模型、引擎、模板和浏览器放入同一成品的构建接线；由于实际模型业务验收未通过，本轮不生成可用包。构建逻辑仅复制锁清单列出的资产，复制前后都核验，不复制下载分片、真实账本、浏览器登录资料或测试输出。

首次管理准备过去分散在单独按钮里，容易出现读取成功却因未建立管理记录而无法启动。现在允许在明确的新列表创建流程中一并建立。**缺少登记不等于首次使用**：已有账户、绑定、删除历史、账本见证、登记目录或外部见证时都不会重新创建；启动自动管理也不会静默初始化。原恢复规则和跨账本未决责任保持。

发生新建列表成功、管理准备失败时，两者分别报告，已创建的列表保留，不能把失败误报成“请重新新建”。若准备过程被中断，已有原计划与见证必须走恢复；不能生成一份空登记来解锁。

状态栏继续显示当前阶段：启动 4B、准备页面、读取或删除确认。已有“中断当前操作”、停止管理和关闭清理继续生效。出现失败时按照固定原因码调查，不把“模型建议完成”当作平台删除成功。

| 遇到的情况 | 当前处理原则 |
| --- | --- |
| 4B 资产不完整或摘要不符 | 停止对应任务，恢复完整包；不自动下载替代模型 |
| 模型超时、输出不合格、页面无法识别 | 停止对应任务并显示原因；不绕开模型偷偷提交 |
| 官方验证码、邮箱核验、登录过期 | 用户在官方页面完成核验后重新读取；不绕过平台机制 |
| 费用不完整、身份/目标变化、表格发生变化 | 不使用旧证据继续自动删除，重新读取或核验 |
| 提交后结果未知 | 保留原 operation 与责任，核实原操作；不能重复提交 |
| 管理登记缺失或存在恢复残留 | 使用管理准备/恢复保留原证据，不清空或重建 |
| 停止/关闭时清理未完成 | 保留相关锁和失败原因，重试当前清理，不杀其他应用进程 |

## 3. 已运行的验证

实际 Qwen3-4B 产品 smoke r2/r3/r4 各计划并执行 **1 例，均未完成**：r2 重复填写相同日期至超时，r3/r4 选择非目标 DSH 项的费用按钮，被请求范围门禁阻止，均未完成费用应用或删除。r4 已改用明显不同的完整合成 UUID，仍出现错目标，不能仅归因于旧测试 ID 过于相似。无模型消融 1 例通过，意义仅为 **0 次目标费用查询、0 次删除提交**；两轮只读诊断分别完成 8 次和 2 次推理，没有证明读取或删除能力改善。详见 [结果与证据限制](operator-product-progress-20261113.md#三已经运行的验证)。

GUI、首次管理准备与打包接线单元已运行 **141 项相关离线测试通过**：新首次准备/原计划恢复 11 项、打包和 CLI 9 项、已有默认值 UI 22 项、启动反馈 9 项、窗口布局 4 项及业务 GUI 86 项。测试输出仍出现既有 Tk 主题关闭事件警告，没有测试失败。这里的数字不包含完整离线回归、真实 4B 在本地网页的验收、成品 EXE 或真实平台验收。

新测试覆盖首次显式准备、未声明时不初始化、已有账户/见证/部分登记阻止重建、中断后保留原计划；以及资产只复制清单成员、摘要失败中止、旧输出不覆盖、离线验收 CLI 不落入正常 GUI。它们使用临时账本、合成资产与本地 Tk，不访问真实平台，不调用真实模型。

另对慢 AI 的证据时限做了源码检查：费用证据仍以采样开始时间计，最大 300 秒；到期或跨日会失效，删除许可前再次检查，不以推理结束时间伪造新鲜度。这个规则未放宽。慢机器、长历史和多目标情况下可能触发重新读取或暂停，需要在真实本地模型/成品验收中记录耗时。

源码提供 `--operator-acceptance --data-dir <全新离线验收目录>` 入口，用于本地网页与内置 4B 的闭环验证。CLI 要求明确目录，与其他验收模式互斥；失败返回非零，不打开正常管理窗口。`passed: true` 必须结合该批次计划解释：无模型保护用例通过不等于正向管理成功。`real_requests: 0` 是该离线模式的报告字段，不是独立网络抓包计数；实际隔离、回环服务器费用/写入到达数及浏览器动作应分别检查。真实模型与最终成品证据不能由模型替身测试代替。

开发者构建示例：

```powershell
python build.py --runtime ./browser-runtime --ai-assets ./local-ai --operator-assets ./operator-ai --output ./dist/DeepSeekQuotaGuardAI
```

三类输入资源均为固定版本；输出必须是不存在的新目录。4B 清单摘要固定，包含模型、官方模板、引擎及所有列出的依赖和许可。构建检查不会把用户自己换模型当成同一已验证版本。

- **先解决实际 4B 在合成页面中的重复无效操作与错目标选择。** 当前尚未取得完整产品业务成功案例，也未运行新主诊断 20 例、留出 20 例、S/N 导航对照或多 seed 稳定性验收。
